# 통합 이동 케어 시연 가이드

[프로젝트 소개](../../README.md) · [빌드 및 Preview](../README.md)

## 시연 목표

가장 가까운 장소보다 사용자의 필수 조건에 맞는 목적지를 먼저 추천하고, 경로 선택·휴식·도착 안내까지 동일한 여정으로 연결하는 과정을 확인합니다.

`mockDebug`의 모든 장소·시설·경로 정보는 가상 데이터입니다. 명령 버튼은 음성 입력을 대신하며 응답은 글로 표시합니다.

## 1. 목적지 비교

홈에서 **케어 안내 보기**를 누르거나 **데모 → 병원 A/B 비교 · 대표 시연**을 선택합니다.

- 검색창에 **병원**을 입력합니다. 검색은 가상 후보 목록을 필터링합니다.
- **무단차 출입구 필수**를 켭니다.
- 병원 A는 5km·12분이지만 필수 조건을 충족하지 않습니다.
- 병원 B는 6km·15분이며 출입구 조건을 충족하는 가상 후보로 우선 추천됩니다.
- 병원 C는 4km·10분이지만 정보 미확인으로 구분됩니다.

병원 B의 **이 목적지 선택 검토 → 확인 후 데모 적용**을 누릅니다. 확인을 취소하면 목적지는 바뀌지 않습니다.

## 2. 편안한 경로 선택

목적지 선택 후 Comfort Care 화면으로 이동합니다.

1. **편안한 경로 선호**를 켭니다.
2. 현재 적용 옵션이 아직 기본 추천 경로인지 확인합니다.
3. **편안한 경로 선택**을 누르고 변경 내용을 확인합니다.
4. **확인 후 데모 적용**을 누르면 적용 옵션이 변경됩니다.

경로 옵션은 Mock 상태만 변경합니다. 실제 경로·ETA를 재계산하지 않으며 도로 진동, 급커브, 승차감이나 멀미 감소 효과를 분석하지 않습니다.

## 3. 이동과 휴식

1. **데모 → 주행 시작**을 선택합니다. 목적지와 적용 옵션이 유지되고 상세 비교·설정은 잠깁니다.
2. **데모 → 휴식 추천**으로 휴식 간격에 도달한 상황을 선택합니다.
3. **조작 → 정차로 전환** 후 Smart Rest에서 휴식 장소를 확인합니다.
4. 기본 설정에서는 무단차 출입구와 장애인 화장실이 있는 것으로 설정된 **푸른뜰 쉼터**를 우선 추천합니다.
5. **장소 상세 → 경유지 추가 검토 → 확인 후 데모 적용**을 누릅니다.
6. 여정에 휴식 경유지가 표시됩니다. **휴식 완료**를 누르면 다음 휴식 추천 시간이 초기화됩니다.

설정에서 **휴식 장소 편의시설 고려**를 끄면 이동 부담이 작은 **가까운 쉼터**가 우선됩니다. 출입구 상태, 시설 상태, 추가 이동 시간과 추천 이유를 함께 비교할 수 있습니다.

## 4. 도착과 하차

1. **데모 → 목적지 접근**을 선택합니다. Arrival Care 안내가 우선됩니다.
2. **조작 → 정차로 전환** 후 도착 화면을 엽니다.
3. 선택한 병원 B의 동쪽 무단차 출입구와 주차·하차 위치 예시를 확인합니다.
4. **데모 → 목적지 도착**으로 전환하고 하차 전 체크리스트와 도착 안내 확인을 진행합니다.

Voice Companion의 **도착 정보 보여줘**도 동일한 목적지 정보를 안내합니다.

## 상태 전환 및 확인 항목

| 조작 | 확인할 내용 |
| --- | --- |
| 무단차 출입구 필수 끄기 | 시간·거리 기준으로 추천 순서가 달라져도 시설의 미확인 상태는 유지 |
| 미확인 후보 선택 검토 | 확인 필요 안내를 표시하고, 동의 전에는 목적지를 변경하지 않음 |
| 변경 확인 창에서 취소 | 기존 목적지·경유지·옵션 유지 |
| 주행 중 | 비교·세부 설정을 잠그고 핵심 여정 안내 표시 |
| SDK 연결 실패 | 유효하지 않은 경로·차량 값을 제거하고 정보 없음 표시 |
| 설정 후 앱 재실행 | 사용자 조건, 휴식 간격, Motion Care, 선호 온도 복원 |

`장시간 이동`, `휴식 추천`, `목적지 접근`, `목적지 도착`은 시간을 건너뛰는 시연 상황입니다. 선택한 목적지·경로 옵션·경유지는 유지하지만 실제 교통이나 위치에 따른 계산은 아닙니다. `정차 중`과 `병원 A/B 비교`는 시연을 초기화합니다. 현재 여정을 유지한 채 멈추려면 **조작 → 정차로 전환**을 사용합니다.
