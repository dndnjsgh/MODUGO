# 앱 구조와 추천 로직

## 구조

Kotlin·Jetpack Compose 기반으로 화면, 상태 처리, 추천 규칙, 데이터 제공부를 구분합니다.

```text
app/src/
├── main/java/com/example/modugo/
│   ├── domain/       모델, 추천 정렬, 이동 케어 규칙
│   ├── data/         데이터 조회·변경 요청 인터페이스
│   ├── mock/         가상 장소, 주행 시나리오, 명령 응답
│   ├── settings/     사용자 조건 저장·복원
│   ├── ui/           Compose 화면, 공통 상태 처리, Preview
│   ├── viewmodel/    화면 수명주기와 상태 처리 연결
│   └── sdk/          경로 수치 검증 및 연동 계약
├── mock/             Mock Repository 구성
├── real/             Pleos SDK 조회 및 UX 제한 어댑터
└── test/             추천·상태 전환·요청 경계 테스트
```

`MainActivity`는 Build Variant에 맞는 Repository를 구성합니다. `ModugoViewModel`은 수명주기를 관리하고, `ModugoStateHolder`가 경로·차량 상태, 사용자 설정과 화면 조작을 결합합니다. 화면은 `ModugoUiState`와 `ModugoActions`를 전달받습니다.

Preview는 같은 상태 처리에 인메모리 Mock과 Compose coroutine scope를 연결합니다. 화면 확인을 위해 실제 SDK나 기기 저장소를 생성하지 않습니다.

## 기능 간 공유 상태

`MobilitySnapshot`은 목적지, 남은 시간·거리, 이동 상태, 선택 경유지, 경로 옵션과 데이터 출처를 공유합니다. `CarePreferences`는 필수 출입구 조건, 휴식 편의시설 선호, 편안한 경로 선호, 음성 안내 선호, 휴식 간격과 Motion Care 설정을 보관합니다.

- Arrival Care의 선택 결과가 여정 목적지가 됩니다.
- Comfort Care는 경로 선호를 제안하고, 확인한 옵션을 여정에 반영합니다.
- Smart Rest는 동일한 사용자 조건을 사용해 휴식 후보를 비교합니다.
- Predictive Journey와 Voice Companion은 같은 목적지·경로 상태를 안내합니다.

## 목적지 추천

1. 무단차 출입구가 필수이면 해당 조건을 먼저 평가합니다.
2. 충족 후보를 먼저 정렬하고, 그 안에서 예상 시간과 거리를 비교합니다.
3. 미확인 후보는 우선 추천하지 않지만 이용 불가로 단정하지 않습니다. 선택 검토 시 확인 필요 안내를 표시합니다.
4. 조건 미충족 후보는 필수 조건이 켜져 있는 동안 선택에서 제외합니다.

필수 조건을 끄면 시간·거리로 비교하지만 장소의 원래 접근성 상태는 바꾸지 않습니다. 목적지를 선택한 뒤 조건을 바꾸더라도 자동으로 다른 목적지로 이동하지 않습니다.

## 휴식 장소 추천

필수 출입구 조건을 우선한 뒤 편의시설 선호가 켜져 있으면 장애인 화장실 상태를 비교합니다. 이어서 추가 이동 시간, 경로 인근 여부, 이동 시간과 거리를 비교합니다. 현재 시설 상태와 경로 관계는 시연 데이터로 제공합니다.

휴식 알림은 설정된 휴식 간격과 마지막 휴식 이후 이동 시간을 기준으로 합니다. 도착이 임박하면 도착 안내가 휴식 알림보다 먼저 표시됩니다.

## 변경 요청과 사용자 확인

`NavigationRequest`는 목적지·경유지·경로 옵션 요청을 구분합니다. 확인 창에는 변경 대상과 추천 이유를 표시하며, 취소하면 기존 상태를 유지합니다.

확인 시점과 실행 직전에 조작 허용 상태, 여정 및 사용자 조건을 다시 검사합니다. 주행 시작·목적지 변경·조건 변경으로 유효하지 않게 된 확인은 재사용하지 않습니다. 실제 SDK 어댑터의 신규 경로 변경 메서드는 기본적으로 요청을 거절합니다.

## 데이터와 UX 경계

- 시설 상태는 확인됨·조건 미충족·미확인을 구분하며 Mock 표식을 표시합니다.
- SDK 연결 실패나 오래된 응답은 유효한 값처럼 유지하지 않습니다.
- 실제 모드의 상세 조작은 플랫폼 CarUxRestrictions 판단을 따릅니다.
- 차량 상태는 조회만 하며 공조·시트·창문 등 장치 제어를 제공하지 않습니다.

실제 데이터와 SDK 연동 범위는 [SDK 문서](SDK_INTEGRATION.md), 동작 검증은 [검증 결과](VALIDATION.md)를 참조하세요.
